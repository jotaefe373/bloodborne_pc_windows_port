## 1. La máscara de reactividad no se guarda ✅ CORREGIDO

### Problema
La casilla "Mostrar máscara (depuración)" del menú funcionaba, pero el ajuste `debug_view` no se guardaba en `bbport.ini`, por lo que después de reiniciar la máscara no se mostraba.

### Causa
En `bbport_settings.cpp`:
- La función `Set()` no procesaba la clave `debug_view`
- La función `Save()` no escribía el valor de `debug_view` en el archivo

### Corrección
**Archivo:** `native_probe/gpu/shim/bbport_settings.cpp`

1. Se agregó el procesamiento en `Set()`:
```cpp
} else if (key == "debug_view") {
    v.debug_view = std::clamp(i, 0, DebugViewCount - 1);
}
```

2. Se agregó la escritura en `Save()`:
```cpp
"debug_view=%d\nshow_fps=%d\n",
// ...
v.debug_view.load(), int(v.show_fps.load())
```

### Cómo verificarlo
1. Iniciar el juego
2. Abrir el menú (Insert o L3+R3)
3. Activar "Máscara de reactividad" → "Mostrar máscara (depuración)"
4. Cerrar el menú
5. La máscara debe mostrarse en color rojo sobre el frame oscurecido

## 2. Estelas en el arma

### Análisis
En los logs se ve:
```
Object motion: on (4194304 vertices per frame)
```

Los vectores de movimiento de objetos están activados y funcionan. Las estelas pueden deberse a:

#### Posibles causas:

**A. Problema de FSR 3.1**
- FSR 3.1 puede procesar mal los objetos que se mueven rápido
- Hay que comparar con FSR 4 (cuando esté implementado)

**B. Los vectores de movimiento de objetos son imprecisos**
- La ruta selectiva activa los vectores solo para los draws con buffers de pose/huesos
- Es posible que el arma en la espalda use otro tipo de animación

**C. La máscara de reactividad no funciona para el arma**
- La máscara marca solo efectos transparentes (partículas, neblina)
- El arma es un objeto opaco, así que la máscara no le afecta

**D. El jitter está desactivado**
En `bbport.ini`:
```
jitter=0
```
El desplazamiento subpíxel está **desactivado**, ¡lo que empeora la calidad del upscaler temporal!

### Recomendaciones para las pruebas

1. **Activar el jitter:**
   ```ini
   jitter=1
   ```
   ¡El jitter es de importancia crítica para FSR 3.1!

2. **Verificar la máscara de reactividad:**
   - Activar `debug_view=1` y `reactive=1`
   - Ver qué áreas quedan marcadas como reactivas
   - El arma NO debe estar en la máscara (es opaca)

3. **Probar a aumentar reactive_scale:**
   ```ini
   reactive_scale=2.00
   ```
   (aunque esto es para la transparencia, no para el arma)

4. **Desactivar los vectores de objetos para comparar:**
   ```ini
   object_motion=0
   ```
   Reiniciar y comparar: ¿empeora o mejora?

5. **Probar distintos presets:**
   - Native AA (preset=0): sin escalado
   - Quality (preset=1): x1.5
   - Performance (preset=3): x2.0
   
   Las estelas deberían ser menores con resoluciones de render más altas.

### Logs para depuración

Activar la depuración de los vectores de movimiento:
```bash
BB_DEBUG_MOTION=1 ./run.sh
```

Deberían aparecer las opciones:
- Toggle 1<<22: reproyección del frame anterior
- Toggle 1<<23: mapa de errores

## 3. Reinicio para aplicar los ajustes

### Situación actual

En los logs:
```
GPU scene scaling: AMD Radeon RX 7800 XT (RADV NAVI32) lacks blit support for D32S8
GPU scene scaling: using startup resolution 960x540 for this driver
```

Tu RX 7800 XT **no soporta blit de D32S8** (copia del buffer de depth+stencil), por lo que se usa la ruta antigua:
- La resolución se fija con un parche al iniciar
- El cambio de preset requiere reiniciar

### Ruta nueva (en el árbol de trabajo, sin commit)

Según ROADMAP.md, en el árbol de trabajo hay código para:
- Escalado dinámico a nivel del renderizador
- Cambio de presets sin reiniciar
- Fallback automático para GPU sin blit de D32S8

Pero este código **todavía no tiene commit**: el autor espera probarlo en una GPU real.

### Qué funciona sin reiniciar

Estos ajustes se aplican **de inmediato**:
- ✅ Activar/desactivar el upscaler
- ✅ Nitidez (sharpness)
- ✅ Jitter (si no está activado BB_LIVE_SCALING_UNSUPPORTED)
- ✅ La máscara de reactividad y sus parámetros
- ✅ Modos de depuración

### Qué requiere reiniciar

En tu GPU:
- ❌ Cambio de preset (Native AA ↔ Quality ↔ Performance)
- ❌ Activar/desactivar los vectores de movimiento de objetos

### Solución alternativa

Para probar distintos presets sin reiniciar el juego:
```bash
# Editar bbport.ini
preset=1  # Quality
# Reiniciar solo el proceso (Ctrl+C, luego ./run.sh)
```

## 4. Hallazgos adicionales

### Configuración de bbport.ini

```ini
upscaler=fsr3
preset=3          # Performance (960x540 → 1920x1080, x2.0)
sharpen=1
sharpness=0.81    # Nitidez alta
jitter=0          # ⚠️ APAGADO: ¡malo para FSR!
reactive=1
object_motion=1
reactive_scale=1.00
reactive_threshold=0.20
reactive_max=0.90
show_fps=1
```

### Ajustes recomendados para la prueba

```ini
upscaler=fsr3
preset=3          # Performance
sharpen=1
sharpness=0.50    # Bajar un poco
jitter=1          # ⚠️ ¡ACTIVAR sí o sí!
reactive=1
object_motion=1
reactive_scale=1.50  # Aumentar para la prueba
reactive_threshold=0.15
reactive_max=0.90
debug_view=1      # Mostrar la máscara
show_fps=1
```
